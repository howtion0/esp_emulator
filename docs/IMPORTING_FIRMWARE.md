# 导入并运行自己的固件

本 Demo 当前针对微雪 ESP32-S3-Touch-AMOLED-1.8 **V2** 的硬件映射。它不会自动把任意 ESP32 固件移植到这块板上。

## 在界面里导入

1. 点击左侧 **＋ 导入固件**。
2. 选择完整 Flash `.bin`，或者 ESP-IDF 工程中的 `build/flasher_args.json`。
3. 导入成功后，固件出现在左侧列表并立即启动；可以停止、重启、触摸以及保存屏幕截图。
4. 后续打开应用，已导入的固件仍保留。运行时 Flash 使用快照，固件对 Flash 的写入在停止后不保留。

应用复制导入文件到自身数据目录，不修改原文件。按最终镜像 SHA-256 去重；不足 16 MB 的完整镜像以 `0xFF` 补齐。界面导入目前检查芯片标识、默认位置的分区表、应用存在性、容量和片段重叠，并不保证所有应用都能在当前外设模型中启动。

## 哪种 BIN 可以导入

支持包含启动器、分区表及应用的**完整 Flash 镜像**。当前配置使用 ESP32-S3、16 MB Flash，启动器位于 `0x0`，分区表位于 `0x8000`。应用偏移从分区表读取。

`build/项目名.bin` 通常只有应用代码，缺少启动器和分区表，不能直接作为整片 Flash 使用。最方便的方式是选择该工程的 `build/flasher_args.json`：保留该目录中 JSON 引用的 bootloader、partition-table 和应用文件，应用会按 `flash_files` 中的偏移读取并合并。

也可以在配置好 ESP-IDF 的终端里生成合并镜像：

```sh
cd build
python -m esptool --chip esp32s3 merge_bin -o merged.bin --fill-flash-size 16MB @flash_args
```

随后导入 `merged.bin`。命令针对项目当前使用的 ESP-IDF/esptool 版本；不同版本的命令名称可能有所区别。

## 没有画面时

先查看右侧日志。确认固件确实为本板 V2 的 CO5300 显示接口与触控连接编译；V1 和其他板型的引脚、控制器可能不同。Wi-Fi、音频、电池和真实 IMU 行为尚未完整模拟，依赖这些功能的应用可能无法继续运行。需要烧录实机的阶段仍应使用真实开发板确认。
